# itVPN: профиль Zhkh и канал АИС ПРИС

Снято 02.11.2026 с файлов в корне репозитория и `itVPN/`.

## Что такое профиль Zhkh и зачем он в комплекте

Заказчик передал **клиентский набор itVPN** (`Zhkh.7z` → `itVPN/Zhkh/`, плюс дистрибутив `Windows_x86_64` и договор с ИТТАС). Это не модуль ПМ и не настройка Django/шлюза.

| Что в имени | Смысл |
|---|---|
| `Zhkh` | Профиль для периметра **ЖКХ** (заказчик / обмен с контуром АИС «Расчет-ЖКУ» и смежными ресурсами), не Минюст |
| `PSZhkH6936U9` | Идентичность PSK этой записи (`psk-identity` / файлы `.ske` / `.ssct2`) |
| `remote 86.57.159.56 39848` | Публичная точка входа **этого** профиля (TCP). За туннелем — внутренняя сеть заказчика; точный хост обмена CSV/API АИС в ovpn не прописан |

**Зачем положили в общий архив с ПРИС:** один комплект «интеграции и защищённый доступ» — клиент itVPN, учебный образец `client.ovpn`, методички ПРИС и профиль Zhkh лежат рядом. Это **разные туннели и разные адресаты**. Профиль Zhkh **не** маршрутизирует на тестовый АИС «ПРИС» `192.168.101.81:10116`.

В `app/` VPN-клиент не встроен: туннель поднимают на хосте сервера (или рабочей станции), приложение ходит уже по маршруту ОС.

`itVPN/Windows_x86_64/client.ovpn` — **учебный образец** дистрибутива (`remote 80.80.80.80`), к Zhkh и к ПРИС не относится.

## Кодировка `Configuration.ovpn`

Файлы `Configuration.ovpn` (корень) и `itVPN/Zhkh/Configuration.ovpn` уже в **UTF-8 без BOM**. Кириллица в комментариях читается нормально, если редактор открывает UTF-8.

Если в Блокноте Windows или в старом редакторе текст «кракозябрами» (`РµР¶РёРј…`), файл открыт как Windows-1251. Нужно: «Открыть с кодировкой UTF-8» или сохранить копию с BOM. Ключевые директивы (`remote`, `psk-file`, `auth-user-pass`) — латиница, на подключение кодировка комментариев не влияет.

## Zhkh ≠ контур ПРИС

| Контур | Куда ходить | Чем поднимать |
|---|---|---|
| Тестовый АИС «ПРИС» (Минюст) | `http://192.168.101.81:10116` | Отдельный itVPN **до сети Минюста**, который выдаёт оператор ПРИС. Профиль Zhkh на `86.57.159.56` этим адресом не является. |
| Профиль Zhkh | Ресурс за `86.57.159.56:39848` (периметр ЖКХ / АИС «Расчет-ЖКУ» у заказчика) | `itVPN/Windows_x86_64` + файлы из `itVPN/Zhkh/` |
| Локальная проверка ПРИС без Минюста | Встроенный стенд шлюза | `GW_PRIS_MODE=channel` — itVPN не нужен |

Методика ПРИС: `itVPN/Сценарии и тесты/2026-10-28 Методичка тестирования интерации с АИС ПРИС — действия модуля.docx`.

## Как включить канал ПРИС (локалка / сервер)

### 1) Без Минюста (локалка, сервер лёг)

В `app/.env` (или compose env шлюза):

```
GW_PRIS_MODE=channel
```

Перезапуск шлюза. Проверка: `GET /gw/v1/integrations/pris/status` — режим `channel`. Пакет в Минюст не уходит, номер производства вида `CH-…`. Логин стенда по умолчанию `channel` / `channel`.

### 2) Живой тестовый контур Минюста

1. На **хосте** (не в контейнере приложения) поднять itVPN, который маршрутизирует до `192.168.101.81`. Профиль для этого выдаёт команда ПРИС/Минюст — **не** Zhkh.
2. Убедиться с хоста: порт `10116` открыт (например `Test-NetConnection 192.168.101.81 -Port 10116`).
3. В `.env` шлюза:

```
GW_PRIS_MODE=http
GW_PRIS_BASE_URL=http://192.168.101.81:10116
GW_PRIS_USER_ID=...
GW_PRIS_ACCESS_KEY=...
```

4. Шлюз остаётся в Docker: исходящий трафик идёт через NAT хоста и туннель. `network_mode: host` не нужен.
5. Проверка маршрута без пакета: `GET /gw/v1/integrations/pris/status` (поле `tunnel`). Echo: `GET /gw/v1/integrations/pris/echo`.

Подробности режимов — `app/STUBS.md` (раздел ПРИС), `app/README.md`.
