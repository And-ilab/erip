# Сервер для ПМ «Модуль по работе с задолженностью»

Один виртуальный сервер, на нём Docker. Windows на сервере не нужна: Django, шлюз, PostgreSQL, Redis и Nginx уже собраны как Linux-контейнеры. Машина разработчика (Windows 10) к требованиям сервера не относится.

Состав один и тот же на тесте и в работе:

| Контейнер | Что внутри | Процессы |
|---|---|---|
| backend | Python 3.11, Django 5, Gunicorn | 4 воркера |
| gateway | Python 3.11, FastAPI, Uvicorn | 2 воркера |
| postgres | PostgreSQL 16 | 1 |
| redis | Redis 7 | 1 |
| nginx | Nginx 1.27, собранный Angular | 1 |

Снаружи открыт порт **8080** (приложение, админка `/admin/`, Swagger шлюза `/gw/docs`). Остальные порты наружу не публикуются.

## Операционная система

| | |
|---|---|
| ОС | Ubuntu Server **24.04 LTS**, 64-bit (x86_64). Подойдёт и 22.04 LTS |
| Не ставить | Windows Server, ОС с графическим рабочим столом |
| ПО | Docker Engine 24 или новее и плагин Docker Compose v2 |
| Диск | SSD. HDD для PostgreSQL не брать |
| Сеть | Вход на порт 8080. Исходящий доступ понадобится позже: тестовый контур ПРИС, почта, SMS |

Часовой пояс приложения — Europe/Minsk, на сервере можно оставить UTC.

## Тестовый сервер

Стенд для проверки и показа: демо-выгрузки, несколько пользователей, без боевых персональных данных на постоянную работу.

| | Не меньше | Нормально |
|---|---|---|
| Ядра | 2 | **4** |
| Память | 4 ГБ | **8 ГБ** |
| Диск | 30 ГБ | **40 ГБ** SSD |

4 ГБ хватает только чтобы контейнеры стартовали. Импорт и четыре воркера Django на таком объёме уже упираются в память. Для стенда заказывать **4 ядра, 8 ГБ, 40 ГБ SSD**.

Куда уходит диск: система и Docker около 10 ГБ, образы около 5 ГБ, база демо-данных и логи — остальное.

## Рабочий сервер

Боевой контур текущего приложения: реальные пользователи организаций, импорт выгрузок АИС, карточки, оповещения, журнал аудита. Каналы почты, SMS и звонков пока заглушки, но место под вложения и рост базы лучше заложить сразу.

| | Не меньше | Нормально |
|---|---|---|
| Ядра | 4 | **8** |
| Память | 8 ГБ | **16 ГБ** |
| Диск | 100 ГБ | **200 ГБ** SSD |

Заказывать **8 ядер, 16 ГБ, 200 ГБ SSD**.

Память складывается так: операционная система и Docker около 2 ГБ, PostgreSQL 4 ГБ, Django (4 воркера) около 2–4 ГБ, шлюз около 1 ГБ, Redis до 1 ГБ, запас на импорт файла в память (лимит загрузки 50 МБ, файл читается целиком).

Диск: система и образы около 20 ГБ, данные PostgreSQL, журнал WAL, выгрузки АИС, будущие PDF (в проверках БНП файл до 15 МБ), логи. 200 ГБ хватает на рабочую базу масштаба сотен тысяч лицевых счетов с исходными строками выгрузки, не на многолетний архив без присмотра.

Отдельный сервер базы на этом этапе не нужен. Резервное копирование тома PostgreSQL — на стороне администратора сервера, в приложении его нет.

## Полный объём из ТЗ (1,5 млн лицевых счетов)

Текущий импорт пишет файл построчно в HTTP-запросе и для 1,5 млн лицевых счетов не рассчитан. Пока этот импорт не заменён пакетной загрузкой, добавлять память бессмысленно: загрузка не станет промышленной.

Когда пакетная загрузка появится, на тот же один сервер ориентир такой:

| | |
|---|---|
| Ядра | 8–16 |
| Память | 32 ГБ |
| Диск | от 500 ГБ SSD |

Исходная строка каждой записи хранится в базе целиком, поэтому лицевые счета вместе с услугами, оплатами и регистрацией занимают заметно больше, чем «одна строка на счёт». 500 ГБ — нижняя оценка с запасом на WAL и вложения, не точный расчёт под живую выгрузку.
